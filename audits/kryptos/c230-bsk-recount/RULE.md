## Criteria (per scope)
- **W ≤ 9:** survivor lines with printed width `w ≤ 9`. **D ≤ 6:** survivor lines with `pop ≤ 6`. (W = 10 is descriptive and not counted.) A line may be in both lists; each list is counted on its own.
- Width and pop are re-derived by me in Python from the printed 24-letter `k=` string (minimal circular window, number of distinct letters), and the 24 shifts themselves are recomputed from (row, dir, X, Y, form) and `alpha.bin`/`themed144.bin`/the bank; every mismatch is listed.

## My cluster rule (one test = one decrypt profile)
Two survivor lines of the same scope and criterion are **the same test iff they give the same decrypt profile**: for each of the 97 plaintext positions i, the set of plaintext letters that the allowed key set can produce from the layer letter at i (layer letter i is ciphertext `C[S[i]]`, S = row for dir 0 or its inverse for dir 1, as the tool). The allowed key set is the observed set of the 24 crib shifts for D, and the minimal covering circular arc (all `w` values) for W, as in PREREG230. The profile is the tuple of 97 26-bit letter masks. Consequences: Vigenère and variant forms of the same (row, X, Y) with negated key merge (identical decrypts), inverse-twin rows merge, a pair of (X, Y) that gives the same decrypt merges; two layouts that differ at any carved position do not merge (the case 210 QWERTY/QWERTZ lesson).
- **Reported per scope/criterion:** raw lines, **cells = distinct profiles**, and (descriptive) distinct (X, Y) pairs.
- **Null-equivalent per scope/criterion:** cells counted on each null (1/20 of the scope), `NE_i = 20 × cells_i`; `NE = mean_i NE_i = (sum_i cells_i) × 20 / 10` (the "×20/10" claim to confirm); also the per-null list and how many nulls have ≥ 1 cell.
- I print, but do not interpret, raw lines per scope. No label (`EXACT-EXCL`, etc.) is assigned here; only counts and the check of her ×20/10 arithmetic.
