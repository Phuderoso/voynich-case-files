## Why
In [C078](C078-paragraph-length-matched.md) the false-positive gates fired 20 times in 240 null replicates (8.3%, nominal 5%), and four tests failed at 3/20. A within-paragraph line-order permutation test applied to line-shuffled data should be exactly valid, so the excess is either chance (plus correlation between replicates drawn from one manuscript) or a bug. This cycle measures it before F-PARA goes on.

## Pre-registration (written before running; tool `tools/c079_gate_audit.py`, seed 7979)
- **Data / statistic:** exactly C078's 12 configurations ({W0, W1, W2} × {Currier A, B} × {IT2a, ZL 3b}) and C078's length-matched statistic LM, imported from `tools/c078_paragraph_lenmatched.py`.
- **Nulls:** 100 fresh true-null pseudo replicates per configuration (lines permuted within each paragraph), each tested with the C078 permutation test (200 permutations). 1,200 null p-values in all.
- **H1 (primary):** pooled rejection rate at α = 0.05. One-sided exact binomial test against 0.05. **INFLATED** if p_binom ≤ 0.05, otherwise **CALIBRATED**.
- **Positive control (required):** a deliberately wrong null that permutes interior *words* among the lines of a paragraph (it ignores line-level clustering), on ZL / Currier B / W0, 100 replicates. It must come out INFLATED (binomial p ≤ 0.05), otherwise the audit has no shown sensitivity and H1 is **NOT TESTABLE**.
- **Descriptive:** rejections per configuration with a chi-square heterogeneity statistic (df 11, critical value 19.68), a KS test of the p-values against uniform, and the probability that a correctly behaving test fails the 20-replicate rule (FPR ≤ 2/20) versus a 40-replicate rule (FPR ≤ 4/40), at both 5% and the observed rate.
- **Fixed interpretation:** CALIBRATED → C078's 8.3% was chance, the gate is valid but coarse, and from C080 on F-PARA gates use 40 replicates (FPR ≤ 4/40, power ≥ 32/40). INFLATED → the C076–C078 permutation machinery has a defect; every F-PARA verdict is flagged until it is found. **C078's verdicts are not revised in either case** (no re-gating after seeing results).

## Results (run 2026-11-09 ~01:58 PT, 146.6 s, seed 7979, 8 processes; `analysis/C079_results.json`, `analysis/C079_raw_pvalues.json`, `analysis/C079_run_log.txt`; pre-registration commit 51f84fe)
- **Two crashes before the valid run, disclosed.** (1) The control job used the key `ZL` instead of `ZL3b` (KeyError, nothing printed). (2) The exact binomial tail overflowed a float after the null p-values were computed; nothing was printed or saved. Both fixes are mechanical (key name; binomial tail in log space). The valid run uses the same seeds, and it now also saves the raw p-values before any summary. Total compute about 9 minutes, over the 8-minute budget.
- **Positive control FAILED:** the word-level permutation null rejected 7/100 times on ZL / Currier B / W0 (binomial p 0.23), so it was not detectably inflated. Under the pre-registered rule **H1 is NOT TESTABLE**: this audit has no demonstrated sensitivity. The control was a plausible misspecification whose inflation was *assumed*, not a test with a *known* wrong size. That was a design error.
- **Descriptive (not a verdict):** 74 / 1,200 true-null replicates rejected at 0.05 (6.2%, Wilson 95% interval 4.9–7.7%; one-sided binomial p 0.040 against 0.05). Rejections per configuration ranged from 2 to 12 out of 100. Heterogeneity chi-square 18.8 on 11 degrees of freedom (critical value 19.68). A KS test of all p-values against uniform gives D 0.026, asymptotic p 0.37.
- **The attainable size is 10/201 = 4.98%,** since p = (1 + b)/201 ≤ 0.05 only when b ≤ 9. Pooling C078's gates (20/240) with this run gives 94 / 1,440 = 6.5%, with a binomial tail of 0.005 against 4.98% (0.037 for this run alone) (post hoc, two looks, descriptive only). A within-paragraph line permutation applied to line-shuffled data should have exact size, so a real excess would point to an implementation defect, for example floating-point near-ties between the observed and permuted statistics. That is a hunch, not a finding.
- **Gate rules at the observed 6.2%:** a correctly sized test fails "FPR ≤ 2/20" 7.5% of the time at nominal size and 12.2% at 6.2%. It fails "FPR ≤ 4/40" 4.8% and 9.8% of the time respectively.
- **Consequences:** C078's verdicts stand, as pre-registered. Every F-PARA rejection so far sits at the permutation floor (p 0.001), far from where a 1–2 point size excess matters. **C080 (pre-committed here):** an exact-size check with a known answer, i.e. a fully synthetic corpus with i.i.d. lines and the same paragraph shapes; a deliberately wrong-size positive control (comparing p to 0.10 while reporting 0.05); and a check of near-ties (statistics rounded to 1e-12).
